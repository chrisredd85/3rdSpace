# Supabase Test Auth Setup

This project uses hosted Supabase Auth for local and E2E signup checks. If Supabase Auth rejects `@example.com` addresses with an "invalid format" error, local QA cannot use the deterministic test emails generated by the Playwright helpers.

## Required project setting

1. Open the Supabase Auth provider settings:
   - https://app.supabase.com/project/rxoyebxazqwknlqvpchc/auth/providers
2. Open the **Email** provider settings.
3. Find the email validation or email restriction setting.
4. Use one of these options:
   - Preferred for this project: add `example.com`, `example.org`, and `test.local` to the allowed test domain list.
   - Alternative for a dedicated development project: disable strict email validation.
   - Alternative for stricter production separation: create a separate Supabase dev project with relaxed email validation and point local `.env.local` at that project.
5. Save the provider settings.

## Verification

After the provider setting changes, test a local signup with:

```text
qa-test@example.com
```

Expected result: Supabase Auth accepts the email format and the app proceeds to the normal signup success or email-confirmation path.

## Test email convention

Use `example.com` for deterministic local and E2E test accounts:

```text
test-<role>-<timestamp>-<random>@example.com
```

This matches `e2e/test-helpers/signup-helpers.ts` and keeps automated test accounts easy to identify and clean up.
